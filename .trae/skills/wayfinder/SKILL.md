一个松散的构想出现了，它大得超出一个 agent 会话所能承载，并且笼罩在迷雾之中：从这里到**目的地（destination）**的道路还看不见。路径探索（wayfinding）是要找到那条路，而不是径直冲向目的地。本技能把这条路绘制成仓库议题追踪器上的一张**共享地图（map）**，然后一次处理一个**决策工单（decision ticket）**（即那种解决方式是一项决策、而非一段待执行构建切片的问题），直到路线变得清晰。

目的地因每次努力（effort）而异，为它命名是绘制地图的第一个动作：它塑造每一个工单。它可能是一份要交接出去并反复迭代的规格、一项要在规划开始前锁定的决策，或是一项原地进行的改动，比如数据结构迁移。地图与领域无关：工程工作、课程内容，任何契合这种形态的东西都行。

## 规划，而非执行

路径探索默认是**规划**：每个工单解决一项决策，当道路清晰、在有人真正动手去做之前再没有什么需要决定时，地图就完成了。那种想直接干活的冲动，通常信号是你已经抵达地图边缘、该交接了。一次努力可以在它的 **Notes** 中覆盖这一默认，把执行纳入地图本身，但除此之外，请产出决策，而不是交付物。

## 以名称相称

每张地图和每个工单都是一个议题，因此它有一个**名称**：它的标题。在人类读到的一切内容中（叙述、地图的 Decisions-so-far），都要用那个名称来指代，绝不要用光秃秃的 id、编号或 slug。一堵 `#42, #43, #44` 的墙无法辨识；名称可以一眼读懂。id 与 URL 并不会消失；名称包裹着它的链接，但它们搭载在名称*之内*，绝不取代名称。

## 地图

地图是本仓库议题追踪器上的单个议题，打上 `wayfinder:map` 标签，是权威产出物。它的工单是地图的子议题。

地图是一份**索引**，而不是仓库。它列出已做出的决策，并指向承载这些决策细节的工单；一项决策只存在于一个地方，即它的工单，所以地图从不复述它，只概述它并给出链接。

**地图、它的子议题、阻塞关系以及前沿查询在物理上存放在哪里，取决于具体追踪器。**议题追踪器应当已经提供给你。如果没有，请告诉用户运行 `/setup-matt-pocock-skills`。查阅追踪器文档的“Wayfinding operations”一节，了解*本*仓库如何表达它们。如果没有提供任何追踪器，默认使用本地 markdown 追踪器。

### 地图正文

整张地图的低分辨率视图，每个会话加载一次。未关闭的工单**不**列出：它们是未关闭的子议题，通过查询找到。

```markdown
## Destination

<what reaching the end of this map looks like: the spec, decision, or change this effort is finding its way to. One or two lines; every session orients to it before choosing a ticket.>

## Notes

<domain; skills every session should consult; standing preferences for this effort>

## Decisions so far

<!-- the index: one line per closed ticket, enough to judge relevance, then zoom the link for the detail the ticket holds -->

- [<closed ticket title>](link): <one-line gist of the answer>

## Not yet specified

<!-- see "Fog of war": in-scope fog you can't ticket yet; graduates as the frontier advances -->

## Out of scope

<!-- see "Out of scope": work ruled beyond the destination; closed, never graduates -->
```

### 工单

每个工单都是地图的一个**子议题**；追踪器的议题 id 就是它的身份。它的正文就是那个问题，大小以一次 100K token 的 agent 会话为度：

```markdown
## Question

<the decision or investigation this ticket resolves>
```

每个工单带有一个 `wayfinder:<type>` 标签，取值之一为 `research`、`prototype`、`grilling`、`task`（见[工单类型](#ticket-types)）。

一个会话通过把工单指派给驱动这张地图的开发者来**认领**它，而且要在任何工作开始**之前**就指派，这样并发会话会跳过它。那个被指派者*就是*认领：一个未关闭且未指派的工单就是未被认领的。

阻塞关系使用追踪器的**原生**依赖关系：这一点至关重要，因为它能在追踪器自己的 UI 中*可视化*地呈现前沿，让人无需打开地图就能看到哪些是可取的。只有缺少原生阻塞功能的追踪器才退回到一种正文约定。当一个工单的所有阻塞工单都已关闭时，它就是**未阻塞的**；**前沿**就是那些未关闭、未阻塞、未被认领的子议题，也就是已知世界的边缘。

答案不属于正文；它在解决时被记录下来（见[按地图推进工作](#按地图推进工作)）。解决某个工单期间创建的资产是从议题链接出去，而不是粘贴进来。

## 工单类型

每个工单要么是 **HITL**（human in the loop，即*与*一个能为自己发言的人类一起工作），要么是 **AFK**，由 agent 独自驱动。HITL 工单只能通过那种实时交流来解决；agent 绝不代替人类那一方（一个自问自答的拷问 agent 已经破坏了这个规则）。

- **Research（研究）**（AFK）：阅读文档、第三方 API 或本地资源（如知识库），以浮现出某项决策所等待的事实。由一个调用 Skill 工具并传入 “research” 的 sub-agent 解决。当需要当前工作目录之外的知识时使用。
- **Prototype（原型）**（HITL）：通过调用 Skill 工具并传入 “prototype”，制作一个廉价、粗糙、具体的产出物（一份提纲、一个粗略的版本、一个桩，或 UI／逻辑代码）供人反应，以此提升讨论的保真度。把原型作为资产链接出去。当“它该长什么样”或“它该如何表现”是核心问题时使用。
- **Grilling（拷问）**（HITL）：对话。默认情形。始终两次调用 Skill 工具，分别传入 “grilling” 和 “domain-modeling”。
- **Task（任务）**（HITL 或 AFK）：在能够做出*决策*之前必须发生的手工工作：没有什么可决定、可打原型或可研究的，但在它完成之前讨论被卡住。注册某项服务以便评判它的 API、开通访问权限、移动数据以便看清它的形状。这是唯一一个*执行*而非决策的类型，它靠解除对某项决策的阻塞来赢得自己的位置，而不是靠交付目的地。agent 在力所能及时独自驱动它（AFK）；否则它交给人类一份精确的清单（HITL）。工作完成时即解决；答案记录做了什么以及后续工单所依赖的任何由此产生的事实（凭据存放位置、新 URL、行数）。

## 战争迷雾

地图是*刻意*不完整的：不要绘制你还看不见的东西。在活跃工单之外是**战争迷雾（fog of war）**：一种对你能看出即将到来、但还无法确定下来的决策与调查的朦胧视野，因为它们取决于仍未解决的问题。解决一个工单会驱散它前方的迷雾，把如今已可规格化的一切逐步升格为新的工单，一次一个，直到通往目的地的道路清晰、不再有工单剩余。

地图的 **Not yet specified** 一节就是记录那种朦胧视野的地方：疑似的问题、以后要重新审视的区域。它是*朝向*目的地的、尚未发现的前沿：这里的一切都在范围内，只是还不够锐利以至于无法立项为工单。视野允许写多松就写多松，允许写多全就写多全；它同时也是一个路标，供协作的人读出这次努力正走向何方。

**是迷雾还是工单？**判断标准是你能不能*现在*就把问题精确地陈述出来，而*不是*你能不能现在回答它。

- **当**问题已经锐利时就立为工单，即使它被阻塞、你还无法对它采取行动。
- **当**你还无法如此锐利地表述它时就写进 Not yet specified。不要预先把这团迷雾切成工单大小的碎块：它比一个工单更粗糙，而前沿抵达它时，一片迷雾可能升格成好几个工单，也可能一个都不升格。

**Not yet specified** 排除已经决定的东西（Decisions so far）、已经成为活跃工单的东西，以及超出范围的东西（下一节）。

## 超出范围

迷雾只会*朝向*目的地聚集。目的地界定了范围，因此超出它的工作就是**超出范围的**：它不是迷雾，也不属于 **Not yet specified**。它在地图上拥有自己的一节 **Out of scope**：你有意识地把这些工作排除在*这一次*努力之外。把它放在这里的是范围，而不是锐利程度。

超出范围的工作永远不会升格（前沿止于目的地），所以只有当目的地被重新绘制时它才会回来，而且是以一次全新努力的形式，而不是接着此前的工作继续。

判定某事物超出范围是一种划界行为，而不是路线上的一个步骤。当某个已经存在的工单原来处在目的地之外时（绘图时被误纳入范围，或被某次解决暴露出来），**关闭它**（已关闭的工单无疑不在前沿上），并在 **Out of scope** 一节留下一行：概述加上它为何超出范围，并链接到那个已关闭的工单。它不进 **Decisions so far**，那一节记录的是实际走过的路线；范围边界不是路线上的一个步骤。

## 调用

两种模式。无论哪种，**每个会话绝不要解决超过一个工单**，研究类工单除外。

### 绘制地图

用户带着一个松散的构想来调用。

1. **命名目的地。**两次调用 Skill 工具，分别传入 “grilling” 和 “domain-modeling”，以确定这张地图正通向什么：那份规格、决策或改动。目的地界定了范围，所以它要最先敲定。
2. **绘制前沿。**再次拷问，这次**广度优先**：在整个空间上铺开，而不是在任一条线索上深入，浮现出未决的决策以及现在就能采取的最初步骤。**如果这没有浮现出任何迷雾**（通往目的地的道路已经清晰，整段旅程小得足以放进一个会话），你就不需要地图。停下来，询问用户希望如何继续。
3. **创建地图**（标签 `wayfinder:map`）：填好 Destination 与 Notes，Decisions-so-far 留空，把迷雾勾画进 **Not yet specified**。
4. **创建你现在就能规格化的工单**，作为地图的子议题，然后在**第二遍**中接好阻塞边（议题需要先有 id 才能互相引用）。接线会把它们分拣成前沿与被阻塞两类；你尚无法规格化的一切都留在迷雾里：即 **Not yet specified** 一节。
5. **启动研究 sub-agent。**对你刚创建的每个 `research` 工单，启动一个调用 Skill 工具并传入 “research” 的 sub-agent，并行解决它，把它的发现记录在一个一次性的 `research/<name>` 分支上，并从工单给出一个上下文指针。
6. 停止：绘图是一个会话的工作量；它不手动解决任何东西。

### 按地图推进工作

用户带着一张地图（URL 或编号）来调用。工单是**可选的**：不带工单时，是你来挑下一个决策，而不是用户。

1. 加载**地图**：低分辨率视图，而不是每个工单的正文。
2. 选择工单。如果用户点名了一个，就用它。否则按顺序取第一个前沿工单。**认领它**：在任何工作之前把它指派给自己。
3. 解决它。**按需放大**：按需获取任何相关或已关闭工单的完整正文；对 `## Notes` 区块点名的任何技能，调用 Skill 工具。如有疑问，两次调用 Skill 工具，分别传入 “grilling” 和 “domain-modeling”。
4. 记录解决结果：把答案作为一条**解决评论**发布，**关闭**议题，并向地图的 Decisions-so-far **追加一个上下文指针**。
5. 添加新浮现出的工单（先创建、后接线）；把答案使其变得可规格化的任何迷雾升格，把每一片升格的迷雾从 **Not yet specified** 中清除，使它只作为其新工单存在。如果答案揭示出某个工单（这一个或另一个）处在目的地之外，就把它**判为超出范围**，而不是在路线上解决它。如果该决策使地图的其他部分失效，就更新或删除那些工单。

用户可能会并行运行未阻塞的工单，所以要有心理准备：其他会话可能正在同时编辑追踪器。
